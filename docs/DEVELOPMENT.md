# Development

## Setup

Requirements: Windows 10/11 x64, Python 3.13, Node.js 22 or newer, Git.

```bat
setup.bat
```

This creates `.venv`, installs the hash-pinned Python dependencies
(`requirements.lock`), installs the package in editable mode, downloads and
verifies the portable PostgreSQL runtime into `runtime\postgresql`, and builds
the web app (`web\dist`). Development tools come from
`requirements-dev.lock`:

```powershell
.venv\Scripts\python -m pip install --require-hashes -r requirements-dev.lock
```

## Everyday workflow

Two terminals, with hot reload for the web app:

```powershell
# 1: API + private PostgreSQL, using a separate development data folder
.venv\Scripts\python -m tg_sales.launcher start --no-browser --data-dir "$PWD\runtime\dev-data"

# 2: web app with hot module reload; /api is proxied to 127.0.0.1:8765
cd web; npm run dev        # http://127.0.0.1:5173
```

For interactive API docs set `TG_SALES_ENVIRONMENT=development` before
starting and open `http://127.0.0.1:8765/api/docs`. Stop with Ctrl+C or
`stop.bat --data-dir ...`.

## Backend

- Code lives in `src/tg_sales` (see [ARCHITECTURE.md](ARCHITECTURE.md) for the
  layers). Put rules in `domain/` (pure functions/dataclasses), database
  queries in `repositories/`, use cases in `services/`, and HTTP in
  `api/routers/`.
- Routers: validate input with a `Body` subclass (rejects unknown fields,
  trims text), call a service, and return a dataclass or Pydantic model.
  Raise `TgSalesError` (or `NotFoundError` / `ConflictError`) with a message
  and a next action for expected failures. Long work goes through
  `ctx.jobs.submit(kind, work)`.
- After changing routes or response models, regenerate the API reference and
  the TypeScript types: `.venv\Scripts\python scripts\generate_api_types.py`
  (the quality gate fails when they are stale).

### Database migrations

The PostgreSQL schema is managed by Alembic (`src/tg_sales/db/migrations_pg`).
Change `db/models.py`, then let Alembic generate the revision against a
throwaway database at the current head:

```powershell
.venv\Scripts\python scripts\new_migration.py "add widget table" 0002
```

Review the generated file in `migrations_pg/versions/` (data migrations,
triggers and seed rows are never autogenerated), then run
`tests/integration/test_migrations.py`, which fails if models and migrations
differ (`test_migrations_match_models`) and checks upgrade/downgrade. Update `docs/DATA_MODEL.md` (the docs test
checks every table and column). Remember: data migrations must be safe on
existing data, and new synchronized tables need a change-log trigger and an
entry in `SYNCED_TABLES`.

## Frontend

- `web/src/features/<screen>/` holds each screen; shared UI is in
  `web/src/components/ui/` (shadcn/ui-style components built on Radix) and
  `web/src/components/layout/`.
- Data: `api.get/post/...` from `lib/api.ts`, cached with TanStack Query.
  Use `useAction` (`lib/hooks.ts`) for mutations (toasts errors, refreshes
  queries) and `useJob` (`lib/jobs.ts`) for background jobs.
- Forms: React Hook Form + Zod where validation is non-trivial; server
  validation is authoritative and its message is always shown.
- Never duplicate business rules in the browser; ask the API.
- Accessibility: every control has a label (`Field` wires labels and errors),
  status is never conveyed by color alone, menus and dialogs come from Radix
  (keyboard and screen-reader support), drag and drop always has a menu
  alternative.
- Theme tokens are in `src/index.css`; use semantic classes (`bg-card`,
  `text-muted-foreground`, `bg-primary`) rather than raw colors.

## Quality gate

```powershell
powershell -File scripts\check.ps1          # ruff, mypy (strict), API types, pytest, tsc, vitest, build
powershell -File scripts\check.ps1 -E2E     # plus Playwright browser tests
powershell -File scripts\check.ps1 -Audit   # plus pip-audit and npm audit (internet)
```

See [TESTING.md](TESTING.md).

## Dependencies

- Python: edit `pyproject.toml`, then `scripts\lock_deps.ps1` (pip-tools with
  hashes and a 14-day cool-down on new uploads).
- Web: `npm install --save-exact <pkg>@<version>` in `web\`, choosing versions
  at least two weeks old; run `npm audit`.
